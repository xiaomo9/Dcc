# dcc 设计决策与变更历史

> 本文件记录 dcc 的设计决策、关键变更和踩坑纪要。用法见 `dcc.md`。

## 关键变更

### 2026-10-21 · `dcc ui` 本地配置面板

通过仅监听本机随机端口、带临时令牌的前台网页管理模型入口与槽位。INI 编辑保留未改动行，保存前校验引用和文件版本；对实际变更的文件做备份与原子替换，按需同步 Claude 模型列表并重载代理。代理快照沿用槽位声明顺序，使首个槽位和 Claude 模型列表的默认项一致。失败时恢复文件与旧代理；停止过的 Claude CLI 会话需要用户手工重开。手动测试连接使用草稿发一条短生成请求，不保存配置。术语见 [CONTEXT.md](../CONTEXT.md)，文件编辑取舍见 [ADR-0001](adr/0001-edit-ini-with-rollback.md)。

验证：完整单元与本地集成测试 56 项通过，覆盖访问令牌、密钥遮挡、三协议模拟生成、INI 注释、槽位顺序、冲突检查、设置同步、备份与失败恢复。临时配置在无头 Chrome 中完成页面截图检查、一次真实表单保存及一次校验错误反馈；测试服务、随机端口代理和浏览器进程已关闭。未向真实网关发送测试请求，也未在真实 VS Code 面板中验证切换与恢复会话。

### 2026-10-21 · `dcc reset` 重新加载代理配置

新增 `dcc reset`，复用现有停止实例、停止代理、固定端口启动代理的流程。代理停止、端口检查与重新启动共用一把生命周期锁，避免另一条启动命令插入。若代理已停止，则直接启动；若停止后配置端口仍被占用，返回错误，避免误报重载成功。`dcc stop` 保持仅停止语义。`dcc reset` 不写入 Claude 用户设置，槽位列表变化后还需执行 `dcc settings` 并重开会话。

### 2026-10-21 · 代理启停互斥与配置变化提示

代理启停复用实例文件的 `fcntl.flock` 模式，使用独立的 `<pidfile>.lock`，覆盖端口检查、配置渲染、进程启动、就绪确认、PID 写入及停止操作。锁文件保留，避免删除后不同进程锁住不同 inode。保护范围是同一输出目录中的新版命令。

健康检查返回后台加载配置的 SHA-256 摘要，复用时与当前渲染配置比较，覆盖模型、密钥、路由、切换与遥测设置。配置变化或旧代理缺少摘要时明确提示手动重启，不自动中断会话，也不覆写后台快照。没有变更时保持静默复用。

验证：先复现启动未等待锁、配置变化未提示两个失败，再完成修复。完整回归 39 项通过，覆盖四进程并发启动唯一代理、启停锁等待、密钥变化提示且不泄露内容、不重启或覆写快照、重启后恢复一致、旧代理缺少摘要兼容，以及原有终端端口回退与三协议测试。仅操作临时配置和本地测试代理，未重启用户代理或进行真实面板验收。

### 2026-10-21 · `dcc stop` 只停止实例和代理

原先 `dcc stop` 将停止与重新加载配置绑定：停止已登记实例、杀掉代理后立即再次启动代理。现在移除自动启动步骤，命令只停止实例和代理，日志字段从 `proxy_restarted` 改为 `proxy_killed`；代理已停止时重复执行也不会启动新进程。需要加载新配置时，明确依次执行 `dcc stop`、`dcc start`，终端用户也可以在停止后运行 `dcc <槽位>` 自动启动代理。帮助、上手指南、面板说明与遥测配置说明已同步。

验证：新增本地代理停止后端口关闭、重复停止不重启、显式再次启动，以及终止登记实例且不启动代理的测试。最终完整回归 35 项通过，`git diff --check` 通过；首轮全量中原有终端启动用例曾超时，单独复跑及最终全量复跑均通过。测试只操作临时目录中的代理和测试实例，未停止用户当前代理。

### 2026-10-21 · `dcc settings` 统一写入模型配置

按确认后的使用方式，新增 `dcc settings`，直接将连接和全部模型列表合并进 `~/.claude/settings.json`，替代下文的早期包装器方案。移除 `src/vscode.py`、包装器脚本及其专属测试；保留固定端口代理命令、服务能力识别、槽位别名和严格路由。命令不启动 Claude 或代理，不修改 VS Code 用户设置。

`src/settings.py` 复用项目现有的同目录唯一临时文件与 `os.replace` 写入方式。保留无关字段和自定义请求头，仅覆盖本地代理、认证、提供方选择、默认模型及模型列表；默认槽位和列表顺序来自配置声明顺序。真实上游地址和密钥仍由代理读取。面板与普通 `claude` 共用该文件，`dcc <槽位>` 继续通过显式参数选择模型。命令固定写入默认用户设置路径，不跟随 `CLAUDE_CONFIG_DIR`。

现有设置在每次实际修改前保存原始字节备份，路径为同目录 `settings.json.dcc-backup-<唯一后缀>` 并打印；新文件和备份权限为 `0600`。内容无变化时不重写或新增备份。JSON、根节点或 env 类型错误、空槽位及备份失败均保持原文件；原子替换失败也保留原文件并清理临时文件，已完成的备份保留。

**验证**：最终运行 `python3.11 -m unittest discover -s tests`，33 项通过，包括首次创建、原字段和请求头合并、全部槽位顺序、不同上游密钥不写入、精确原文备份、重复执行、错误配置、备份/替换失败，以及写配置后终端显式选模型和端口偏移。原有三协议、路由、切换、工具、thinking、统计和多实例测试继续通过。语法检查与 `git diff --check` 通过。使用临时 HOME 和独立 Claude 配置目录，扩展自带 Claude 2.1.305 无包装器、无内联设置初始化成功，从生成的设置文件返回全部 8 个槽位及 Default 行。

**验收边界**：本轮没有可用的电脑控制工具，未完成真实 VS Code 面板发送两个槽位请求、日志核对、切换与历史恢复验收；没有连接真实网关发送对话。客户端初始化不等同于面板端到端验收。验证仅使用临时设置文件，未修改本机实际 Claude/VS Code 用户设置，也未重启原有代理。配置与恢复步骤见 [使用说明](../dcc.md#vs-code-claude-code-聊天面板)。

### 2026-10-21 · VS Code Claude Code 面板接入（早期包装器方案，已替代）

新增 `dcc start`，仅启动或复用配置端口上的代理，其他服务或旧版代理占用端口时明确报错。健康响应增加 `service: "dcc-proxy"` 和 `capabilities: ["vscode"]`，避免面板连接到不支持严格路由的旧代理。普通终端启动仍保留端口偏移行为。

`vscode-claude-wrapper.sh` 接收扩展传入的 Claude 二进制和参数，由 `src/vscode.py` 合并进程级 `--settings`，注入本地代理、默认槽位和模型列表；保留扩展权限设置、工作目录及标准输入输出，不写共享 Claude 设置或更换历史目录。面板进程由扩展管理，不加入终端实例登记。

实际使用扩展自带 Claude 2.1.304 初始化时，直接使用本地模型名只返回了 7/8 个槽位，旧 Opus 槽位被客户端隐藏；禁用旧模型重映射也没有恢复。因此面板改用 `dcc-slot-<槽位>` 加原上下文后缀作为内部 ID，显示名称仍是槽位和真实本地模型名。再次初始化确认 8 个槽位全部返回，另有客户端保留的 Default 行。仅带 `x-dcc-client: vscode` 的请求识别这些别名，未知模型返回 404 错误 JSON；候选链仍从已解析的实际模型生成。

**验证**：2026-10-21 最终运行 `python3.11 -m unittest discover -s tests`，30 项通过，覆盖固定端口启动与复用、其他服务识别、终端端口偏移、真实 shell 包装器参数透传和设置合并、空槽位、代理未启动、严格路由与槽位别名，以及原有三协议、切换、统计和多实例测试。Python 语法检查与 `git diff --check` 通过。扩展自带二进制的版本调用和 SDK 初始化通过，但没有发送真实网关对话。

**尚未完成的验收**：真实 VS Code 面板中的两个槽位发送请求、切换后的日志核对、新建/恢复会话及代理未启动的 UI 提示。上一轮临时工作区处于受限模式；本轮电脑控制工具报 `Sky Computer Use native pipe startup failed`，无法继续 UI 操作。二进制初始化和模拟 HTTP 测试不视为面板端到端验收。全局 VS Code/Claude 配置和原有运行代理未改动。

**客户端限制**：启动包装器会使扩展跳过同一会话在其他进程打开的检查，并影响部分计划模式恢复；面板切换不动态应用逐槽位 `autoCompactWindow`。配置方法、回退步骤及限制见 [面板接入说明](../dcc.md#vs-code-claude-code-聊天面板)。

### 2026-10-20 · 切换条件与软超时连接回收

OpenAI 和 Responses 的候选守卫现在只在上游返回可重试状态且 `switch_on_429=true` 时切换；400 等不可重试错误直接返回。`switch_on_429=false` 时，429 留在原模型退避重试，守卫请求计入原有 `MAX_RETRIES + 1` 次总请求预算。首字节软超时后标记守卫请求已取消，关闭尚未移交的连接；若连接稍后才建立，由工作线程立即关闭，避免迟到响应留在后台。

无监听端口的检查已验证 OpenAI / Responses 对 400、关闭切换的 429、开启切换的 429 的分支和请求次数；连接回收与移交竞态测试、流转换测试通过。完整本地 HTTP 测试因本次自动审批额度限制未能运行，真实网关与 Claude Code 未实测。

### 2026-10-20 · 上游错误返回与多会话实例管理

**上游错误返回**：OpenAI、Responses 原先把部分失败写进 assistant 正文；非流式聚合也会把 Anthropic 的错误事件转成普通消息。现在由 `UpstreamFailure` 保存状态码、错误类型与消息，在 HTTP 出口统一返回：流式发送 SSE `error`，非流式返回错误 JSON。上游 HTTP 错误保留状态码；无上游错误状态时，超时映射 504，连接失败、截断及流内错误映射 502。终止失败不再补发正常结束事件，已输出内容不重放。重试预算、候选顺序和切换条件保持不变。

**多会话实例**：`instances.json` 从槽位键改为 PID 字符串键，保留 `slot`、模型、目录和启动时间等字段。同槽位可登记多个实例。读取时兼容旧格式，下一次写入保存新格式；旧版已经覆盖丢失的记录无法恢复，不保证新旧版本并发写入兼容。独立锁文件配合 `fcntl.flock` 保护读取、清理、更新和写入，同目录唯一临时文件加原子替换避免半截 JSON。

`status` 展示全部已登记的存活实例；内部按槽位停止会处理该槽位的全部实例，`stop_all` 按实例统计成功发送的信号数。保留自身保护，信号发送失败不删除记录。`dcc stop` 仍执行停止 CC、停止代理、重启代理，不新增命令。存活判断沿用 PID 检查，本次未增加进程身份验证。

**验证**：本次实现后执行 `python3.11 -m unittest discover -s tests -v`，19 项测试通过。包括本地 HTTP 模拟上游的三协议流式/非流式失败、429 重试耗尽、连接异常、超时、截断、流内错误、首帧后不切换及成功候选不重放；实例测试覆盖同槽位多实例、6 个进程并发登记、旧格式兼容、死亡记录清理、停止失败、自身保护和写入失败保留原记录。原有工具调用、thinking、切换与统计测试通过。

**验证边界**：没有连接真实网关验证，也没有实测真实 Claude Code 的错误展示和客户端重试行为；本地测试不等同于这些端到端验收。本次实现与验证未重启正在运行的代理。

### 2026-08-19(v0.1.15)· 修 stream=false bug

`_handle_messages` 之前无条件回 SSE,CC 内部非流式重试(slot 上游 429 后触发)会收到 event-stream body 报错"non-streaming request was answered with a stream"。现在按 body.stream 分流:True 保 SSE;False 用 `_BufWFile` 缓冲三条 stream_*_to_anthropic 的 SSE 输出,`collect_sse_to_message` 聚合成 anthropic Message JSON(Content-Type: application/json)一次性回。openai/responses/anthropic 三协议 × true/false 六组 curl 验证通过。

### 2026-08-19(v0.1.16)· 图文能力守卫

`~/.dm/llm.ini` 每 section 支持 `supports_images = true|false`(缺省 false 保守)· `false` 时 proxy 层剥掉历史 `image`/`image_url` block(避免 GLM/DeepSeek 等纯文本模型收到图片直接 400)· 剥离后:openai/responses 分支 SSE 首帧插入 `[dcc] ⚠️ 本 slot 不支持图文 · 已剥离 N 张历史图片…` 明文提示,anthropic 分支通过响应头 `x-dcc-warn-images-stripped: N` + proxy log WARN 提示。要开图文能力的 slot,在对应 llm.ini section 加 `supports_images = true`(先确认模型确实支持 vision)。
